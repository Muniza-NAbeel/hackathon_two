## Summary

Build a Python 3.13+ command-line Todo application with in-memory storage. The application implements 5 core features (Add, Delete, Update, View/List, Mark Complete/Incomplete) through an interactive menu-driven console interface. ## Task Model Definition

### models.py - Task Dataclass

```text
Task:
    id: int                          # Unique identifier (auto-increment, never reused)
    title: str                       # Brief name (required, max 100 chars)
    description: str = ""            # Detailed info (optional, max 500 chars)
    is_completed: bool = False       # Completion state
    created_at: datetime             # Auto-generated timestamp
```

### Field Constraints

| Field | Type | Constraint | Default |
|-------|------|------------|---------|
| `id` | int | Auto-generated, >= 1, never reused | N/A (required) |
| `title` | str | Required, 1-100 chars after trim | N/A (required) |
| `description` | str | Optional, 0-500 chars after trim | `""` |
| `is_completed` | bool | True or False | `False` |
| `created_at` | datetime | Auto-generated at creation | `datetime.now()` |

## Menu & UX

### Console Menu Layout

```
====================================
       TODO APPLICATION
====================================

1. Add Task
2. View Tasks
3. Update Task
4. Delete Task
5. Toggle Complete/Incomplete
6. Exit

Enter your choice (1-6): _
```

### Status Indicators

| Status | Indicator | Example |
|--------|-----------|---------|
| Incomplete | `[ ]` | `[ ] #1: Buy groceries` |
| Complete | `[✓]` | `[✓] #2: Call dentist` |

### Operation Flows

**1. Add Task**:
- Prompt for title (required)
- Prompt for description (optional, Enter to skip)
- Create task with auto-ID and timestamp
- Display success with task details
- Press Enter to return to menu

**2. View Tasks**:
- If empty: "No tasks yet! Use 'Add Task' to create your first task."
- If tasks exist: Display all with status, ID, title, description preview, timestamp
- Show summary: "Total: X tasks (Y completed, Z incomplete)"
- Press Enter to return to menu

**3. Update Task**:
- Prompt for task ID
- Validate ID exists
- Display current task
- Prompt for new title (Enter to keep current)
- Prompt for new description (Enter to keep current)
- Display updated task
- Press Enter to return to menu

**4. Delete Task**:
- Prompt for task ID
- Validate ID exists
- Display task to delete
- Confirm: "Are you sure? (y/n)"
- Delete on 'y', cancel on 'n'
- Press Enter to return to menu

**5. Toggle Complete/Incomplete**:
- Prompt for task ID
- Validate ID exists
- Toggle is_completed
- Display new status
- Press Enter to return to menu

**6. Exit**:
- Display goodbye message
- Terminate application

## Input Validation & Error Handling

### Validation Rules

| Input | Validation | Error Message | Recovery |
|-------|------------|---------------|----------|
| Menu choice | Must be 1-6 (numeric) | "Invalid option. Please enter 1-6." | Re-display menu |
| Task ID | Must be positive integer | "Please enter a valid task ID (number)." | Re-prompt |
| Task ID | Must exist in storage | "Task #X not found." | Return to menu |
| Title | Non-empty after trim | "Title cannot be empty." | Re-prompt |
| Title | Max 100 chars | "Title truncated to 100 characters." | Warning, continue |
| Description | Max 500 chars | "Description truncated to 500 characters." | Warning, continue |

### Error Display Patterns

```text
[ERROR] Invalid option. Please enter 1-6.
[WARNING] Title truncated to 100 characters.
[SUCCESS] Task created successfully!
```

### Whitespace Handling

All text inputs are trimmed of leading/trailing whitespace before processing (FR-012).

## Future Extensibility

### Storage Interface Pattern

The `TaskStorage` class is designed as a replaceable interface:

```text
Phase I:  TaskStorage (in-memory dict)
Phase II: JsonTaskStorage (file persistence)
Phase II+: PostgresTaskStorage (Neon database)
```

All implementations share the same interface methods:
- `create()`, `read()`, `read_all()`, `update()`, `delete()`, `next_id()`

### Serialization Preparation

Task dataclass supports JSON serialization:
- `dataclasses.asdict()` for dict conversion
- `datetime.isoformat()` for JSON-safe timestamps
- `datetime.fromisoformat()` for reconstruction

### Potential Enhancements (Out of Scope for Phase I)

- Due dates: `due_at: Optional[datetime]`
- Priorities: `priority: int` (1-3)
- Categories: `category: str`
- Sorting/filtering functions
