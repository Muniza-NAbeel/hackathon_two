# Implementation Plan: Phase 5 - Advanced Cloud Deployment

**Branch**: `5-phase5-cloud-deployment` | **Date**: 2026-01-18 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/005-Advanced-Cloud-Deployment/spec.md`

## Summary

Phase 5 transforms the Phase 3/4 monolithic chatbot into a production-grade, event-driven microservices architecture. Key deliverables include:
- Kafka/Redpanda for event streaming with CloudEvents format
- Two new microservices: Notification Service and Recurring Task Service
- Dapr integration for Pub/Sub, State Management, Bindings, and Secrets
- Local deployment via Minikube with Redpanda and Redis
- Cloud deployment to DOKS/GKE/AKS with managed services
- CI/CD pipeline via GitHub Actions

## Technical Context

**Language/Version**: Python 3.11+ (Backend Services)
**Primary Dependencies**: FastAPI, SQLModel, Dapr SDK, httpx, Official MCP SDK, OpenAI Agents SDK
**Storage**: Neon PostgreSQL (existing), Redis (local state), Dapr State Store
**Testing**: pytest, pytest-asyncio
**Target Platform**: Kubernetes 1.28+ (Minikube local, DOKS/GKE/AKS cloud)
**Project Type**: Microservices (Backend Services + Event Consumers)
**Performance Goals**:
- Event processing latency < 2 seconds
- 1000+ concurrent users
- Kafka throughput 1000 events/second
**Constraints**:
- Dapr runtime 1.12.0+
- Stateless microservices
- Idempotent event processing (24h deduplication)
- Phase 3/4 code READ-ONLY
**Scale/Scope**: 3 services, 3 Kafka topics, 4 Dapr components

## Architecture Decisions Summary

| Decision | Rationale | Alternatives Rejected |
|----------|-----------|----------------------|
| Redpanda over Apache Kafka | Simpler deployment, Kafka API compatible | Apache Kafka (complex ZooKeeper setup) |
| Dapr for abstractions | Cloud-native, multi-cloud portable | Direct Kafka SDK (vendor lock-in) |
| Redis for local state | Simple, fast, Dapr native support | PostgreSQL (overkill for idempotency) |
| FastAPI for services | Consistent with Phase 3/4, async native | Flask (no async), Go (different stack) |
| CloudEvents format | Industry standard, extensible | Custom schema (non-standard) |
