# Implementation Plan: Phase 4 - Local Kubernetes Deployment (Minikube)

**Branch**: `004-minikube-deployment` | **Date**: 2026-01-13 | **Spec**: [specs/004-minikube-deployment/spec.md](./spec.md)

## Summary

Deploy the Phase 3 AI-powered Todo Chatbot application to a local Kubernetes cluster using Minikube. This is a deployment-only phase with no application code changes. All infrastructure artifacts (Dockerfiles, Helm charts, Kubernetes manifests) will be generated using AI-assisted tools following Spec-Driven Development principles. Phase 3 code remains READ-ONLY.

## Technical Context

**Language/Version**: Python 3.11+ (Backend), TypeScript/Node.js 18+ (Frontend)
**Primary Dependencies**: Docker 24+, Minikube 1.32+, Helm 3+, kubectl
**Storage**: Neon PostgreSQL (external, existing from Phase 3)
**Testing**: Manual verification via browser and kubectl commands
**Target Platform**: Local Kubernetes (Minikube) with Docker driver
**Project Type**: Web application (frontend + backend containers)
**Performance Goals**: Services healthy within 60 seconds, chatbot response <5 seconds
**Constraints**: Phase 3 code immutable, minimum 4 CPU / 8GB RAM for Minikube
**Scale/Scope**: Single-node local cluster, 1 replica per service

**Actions**:

**Verification**: Directory structure exists with correct hierarchy

### Step 2: Backend Dockerfile Generation (AI-Assisted)

**Objective**: Generate optimized multi-stage Dockerfile for FastAPI backend.

**AI Tool**: Docker AI Agent (docker-ai-agent skill)

**Actions**:
1. Analyze `phase_3/backend/` structure (requirements.txt, app/ structure)
2. Generate multi-stage Dockerfile with:
   - Stage 1: Python 3.11-slim base with dependencies
   - Stage 2: Production image with non-root user
3. Create `.dockerignore` to exclude tests, __pycache__, .env files
4. Build and verify image: `docker build -t todo-backend:latest`

**Key Considerations**:
- Use `COPY --from` to reference `phase_3/backend/` source
- Expose port 8000 for FastAPI
- Set PYTHONUNBUFFERED=1 for container logging
- Run as non-root user (uid 1000)

**Verification**: `docker run --rm todo-backend:latest` starts without errors

---

### Step 3: Frontend Dockerfile Generation (AI-Assisted)

**Objective**: Generate optimized multi-stage Dockerfile for Next.js frontend.

**AI Tool**: Docker AI Agent (docker-ai-agent skill)

**Actions**:
1. Analyze `phase_3/frontend/` structure (package.json, next.config.js)
2. Generate multi-stage Dockerfile with:
   - Stage 1: Node 18-alpine with dependencies install
   - Stage 2: Build stage with `npm run build`
   - Stage 3: Production image with standalone output
3. Create `.dockerignore` to exclude node_modules, .next cache, .env files
4. Build and verify image: `docker build -t todo-frontend:latest`

**Key Considerations**:
- Use Next.js standalone output mode for minimal image
- Expose port 3000 for Next.js
- Set NODE_ENV=production
- Run as non-root user (uid 1000)

**Verification**: `docker run --rm todo-frontend:latest` starts without errors

### Step 4: Backend Helm Chart Generation (AI-Assisted)

**Objective**: Generate Kubernetes Helm chart for backend deployment.

**AI Tool**: Helm Chart Agent (helm-chart-agent skill)

**Actions**:
1. Create `phase_4/helm/backend/Chart.yaml` with metadata
2. Create `phase_4/helm/backend/values.yaml` with configurable values:
   - Image repository and tag
   - Replica count (default: 1)
   - Resource limits (CPU: 500m, Memory: 512Mi)
   - Environment variables placeholders
3. Generate templates:
   - `deployment.yaml`: Pod spec with probes
   - `service.yaml`: NodePort service (port 30080)
   - `configmap.yaml`: Non-sensitive environment variables
4. Validate chart: `helm lint phase_4/helm/backend`

**Key Configurations**:
- Liveness probe: `/health` endpoint, initial delay 30s
- Readiness probe: `/health` endpoint, initial delay 10s
- Environment variables via ConfigMap and Secrets

**Verification**: `helm template backend phase_4/helm/backend` renders valid YAML

### Step 6: Minikube Cluster Setup

**Objective**: Start and configure local Kubernetes cluster.

**AI Tool**: Minikube Deployment Agent (minikube-deployment skill)

**Actions**:
1. Start Minikube with adequate resources:
   ```bash
   minikube start --cpus=4 --memory=8192 --driver=docker
   ```
2. Enable required addons:
   ```bash
   minikube addons enable metrics-server
   ```
3. Configure Docker environment for Minikube:
   ```bash
   eval $(minikube docker-env)
   ```
4. Verify cluster is ready:
   ```bash
   kubectl get nodes
   ```

**Verification**: `kubectl cluster-info` shows healthy cluster

---

### Step 7: Build Docker Images in Minikube

**Objective**: Build Docker images inside Minikube's Docker daemon.

**Actions**:
1. Ensure Docker environment is set to Minikube:
   ```bash
   eval $(minikube docker-env)
   ```
2. Build backend image:
   ```bash
   docker build -t todo-backend:latest -f phase_4/backend/Dockerfile phase_3/backend
   ```
3. Build frontend image:
   ```bash
   docker build -t todo-frontend:latest -f phase_4/frontend/Dockerfile phase_3/frontend
   ```
4. Verify images exist:
   ```bash
   docker images | grep todo
   ```

**Verification**: Both `todo-backend:latest` and `todo-frontend:latest` appear in image list

---

### Step 8: Deploy Backend to Kubernetes

**Objective**: Install backend Helm chart to Minikube cluster.

**AI Tool**: Minikube Deployment Agent (minikube-deployment skill)

**Actions**:
1. Create Kubernetes secret for sensitive environment variables:
   ```bash
   kubectl create secret generic backend-secrets \
     --from-literal=DATABASE_URL="${DATABASE_URL}" \
     --from-literal=GEMINI_API_KEY="${GEMINI_API_KEY}" \
     --from-literal=JWT_SECRET="${JWT_SECRET}"
   ```
2. Install backend Helm chart:
   ```bash
   helm install backend phase_4/helm/backend \
     --set image.repository=todo-backend \
     --set image.tag=latest \
     --set image.pullPolicy=Never
   ```
3. Wait for deployment to be ready:
   ```bash
   kubectl rollout status deployment/backend --timeout=120s
   ```

**Verification**: `kubectl get pods -l app=backend` shows 1/1 Ready

---

### Step 9: Deploy Frontend to Kubernetes

**Objective**: Install frontend Helm chart to Minikube cluster.

**Actions**:
1. Get backend service URL for frontend configuration:
   ```bash
   BACKEND_URL="http://backend:8000"
   ```
2. Install frontend Helm chart:
   ```bash
   helm install frontend phase_4/helm/frontend \
     --set image.repository=todo-frontend \
     --set image.tag=latest \
     --set image.pullPolicy=Never \
     --set env.NEXT_PUBLIC_API_URL="${BACKEND_URL}"
   ```
3. Wait for deployment to be ready:
   ```bash
   kubectl rollout status deployment/frontend --timeout=120s
   ```

**Verification**: `kubectl get pods -l app=frontend` shows 1/1 Ready
